# E02 Learning View

## Core Idea

Project E 的学习目标不是“尽快复刻出一个能跑的命令”，而是理解 AugMPC 这类 RL + MPC 项目的复现为什么天然要分层。

## What Each Stage Teaches

| Stage | What To Learn |
|---|---|
| E00 | 学会先校正学习对象。项目目标错了，后续任何努力都不经济。 |
| E01 | 学会识别 RL + MPC 复现中的三层结构：算法代码、框架索引、容器执行入口。 |
| E02 | 学会设计复现流程本身。复杂项目不能只靠 README 顺序阅读，需要阶段化建模。 |
| E03 | 学会区分“公开展示层”和“公开可复现层”。有页面、有路径、有说明，不代表真的能无损复现。 |
| E04 | 学会把系统依赖拆成认证、GPU、显示、挂载、存储等层，而不是笼统地说“环境不行”。 |
| E05 | 学会把分散在 README、脚本和 bundle 约定里的信息收敛成未来可执行命令。 |
| E06 | 学会把过程审计收束成自己的理解，解释 AugMPC 的价值、边界和后续投入回报。 |

## Why This Matters For AugMPC

- AugMPC 不是单一 Python 包，而是跨算法、共享内存、MPC 集群、仿真接口、容器、bundle 的复合系统。
- 这类项目最容易出现“读起来像能跑，真正执行时才发现缺资源、缺权限、缺私有依赖”的情况。
- 因此，Project E 的学习路线必须先训练“识别边界”和“分层定位”的能力，再考虑未来执行。

## E02 Learning Outcome

E02 完成后，预期获得的不是新运行结果，而是一个更强的判断能力：

- 知道为什么 `Centauro / B2W` 更适合作为先期公开目标。
- 知道为什么 `Kyon` 和 `u24` 不适合当前阶段当第一执行目标。
- 知道为什么 E03-E05 必须继续保持只读、延后执行的约束。

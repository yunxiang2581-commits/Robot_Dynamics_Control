# AGENTS.md

## 项目目标
本仓库用于分步骤学习机器人运动学、动力学与控制。

当前主线：
1. URDF 导入
2. FK
3. Jacobian
4. IK
5. 动力学项
6. 控制原型

目标不是只求“尽快写完代码”，而是：
- 理解每一步原理
- 学会手动编写关键代码
- 让 Codex 作为助教、骨架生成器、审阅者

---

## 工作原则
优先：
- 先解释原理和原因
- 先说明这一步和主线的关系
- 先生成骨架，再逐步补全
- 保留 TODO，给用户手动实现空间
- 保持代码简单、清晰、可运行

避免：
- 未经要求重写整个文件
- 直接生成大而全的成品
- 过早抽象成复杂框架
- 跳过当前基础步骤直接做后续高级任务

---

## Codex 的角色
Codex 应作为：
- 编程助教
- 骨架生成器
- 小范围补全工具
- 审阅与调试助手

Codex 不应作为：
- 一次性整包代写工具
- 无解释的代码倾倒器
- 未经要求的重构器

推荐顺序：
1. 解释原理
2. 生成带注释骨架
3. 用户手动补关键逻辑
4. Codex 做补全或审阅
5. 验证结果并解释

---

## 代码规则
- 尽量保留现有结构、变量名、函数名
- 学习脚本优先使用清晰的 `main()`
- 不要无故新增无关文件
- 不要把学习型代码改成难读的“高级写法”
- 除非明确要求，否则优先生成“骨架 + TODO”，不是完整实现

---

## 注释规则
所有学习脚本都应包含**充足的中文注释**。

每个主要代码块应说明：
1. 这一部分做什么
2. 为什么这一步需要做
3. 推荐用什么函数 / 方法 / API
4. 输入是什么
5. 输出是什么

每个 TODO 应说明：
1. 要补什么
2. 推荐用什么函数
3. 补完后应该得到什么结果

---

## 路径处理规则
“路径设置”是本仓库的正式学习内容。

要求：
- 不依赖 shell 当前工作目录
- 使用 `pathlib.Path`
- 优先通过 `__file__` 定位项目根目录
- 使用候选路径列表查找 URDF / 模型资源
- 自动创建输出目录
- 找不到文件时给出明确报错

推荐写法：
- `PROJECT_ROOT = Path(__file__).resolve().parents[1]`
- `URDF_CANDIDATES = [...]`
- `OUT_DIR = PROJECT_ROOT / "outputs" / <task_name>`
- `OUT_DIR.mkdir(parents=True, exist_ok=True)`

---

## 模型搜索规则
“目标模型搜索”也是本仓库的正式学习内容。

在选择 frame / joint 时：
- 不要凭猜测写死名字
- 先精确匹配
- 再包含匹配
- 对重要目标使用候选列表

推荐学习并使用：
- `model.names`
- `model.frames`
- `[f.name for f in model.frames]`
- `model.getFrameId(name)`
- `model.getJointId(name)`

## Pinocchio 规则
在相关任务中，优先解释这些概念：
- 固定基 vs 浮动基
- `nq` vs `nv`
- `pin.JointModelFreeFlyer()`
- `pin.neutral(model)`
- `forwardKinematics`
- `updateFramePlacements`
- `computeJointJacobians`
- `getFrameJacobian`
- `integrate`

每个脚本尽量说明：

- 当前在算什么

- 这一步连接到主线中的哪一环

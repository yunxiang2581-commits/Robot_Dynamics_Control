## 3. 今日理解

- `StateEst` 不是可有可无的平滑器，而是 `walk_wbc` 里 floating-base base 状态的正式来源。
- `MJ_Interface + DataBus::updateQ()` 只负责先拼一版原始 `q/dq`。
- 真正给后续 `Pin_KinDyn / WBC / 控制器` 使用的 base 状态，是在 `StateEst::get()` 中重新写回的。
- `StateEst::update()` 不是只做 prediction，而是完整的 Kalman 状态估计递推：

```text
prediction + correction
```

- `StateEst` 的核心思想可以概括为：

```text
IMU 告诉估计器“机器人大概怎么动了”
支撑脚告诉估计器“机器人不应该漂到哪里去”
```

- `Eul_W_filter` 的预测值不是为了控制下一步动作，而是为了给当前状态估计提供先验参考，使姿态和角速度更平滑、更连续。
- `getTrustRegion_wt_h()` 的作用不是算状态，而是把：
  - 当前哪只脚接触
  - 当前相位 `phi`
  转成脚位置/脚速度/脚高度约束的本拍权重。

## 4. 第三轮收口结论

第三轮阅读可以收口为这条链：

```text
MuJoCo 原始观测
-> MJ_Interface / DataBus::updateQ() 拼原始 q/dq
-> StateEst::set() 读取并预处理观测
-> StateEst::update() 用 IMU prediction + 支撑脚约束 correction 做状态估计
-> StateEst::get() 把估计结果写回 base_* 和 q/dq
-> 后续 Pin_KinDyn / WBC / 控制器使用的是估计后的 floating-base 状态
```

## 3. 今日理解

- `walk_wbc` 是真实闭环入口：`mj_step` 后读取 MuJoCo 状态，再经过 StateEst、Pin_KinDyn、步态、落脚、WBC、PVT，最后把 `motors_tor_out` 写回 `mj_data->ctrl`。
- `wbc_speed_test` 只使用固定 sample state 做 non-viewer benchmark，不能代表完整仿真闭环。
- `walk_wbc` 中 WBC 输出会转成期望关节位置、速度和力矩；C05A 中这段转换是注释掉的。
- `MJ_Interface::dataBusWrite()` 没有直接写入 base position / base linear velocity，说明 `StateEst` 在真实闭环里不是可忽略模块。
- `WBC_priority` 会写出 `qp_status`、`wbc_tauJointRes`、`wbc_FrRes`，但当前 `walk_wbc` datalog 未记录这些字段。
- `MJ_Interface` 构造函数的关键作用不是读状态，而是建立：
  - `JointName -> qpos index`
  - `JointName -> qvel index`
  - `JointName -> actuator id`
- 第二轮应先只追 `mj_step -> MJ_Interface::updateSensorValues() -> dataBusWrite() -> DataBus::updateQ()`，不要过早跳进 `StateEst` 或 `WBC_priority`。
- 对 `walk_wbc` viewer 而言，当前真正的风险已经不在 `walk_wbc.cpp` 源码本身，而在容器运行时的 X11 / OpenGL / RUNPATH / 动态库链路。

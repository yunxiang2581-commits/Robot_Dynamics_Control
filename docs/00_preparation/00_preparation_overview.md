## 本文用途

本文件说明为什么要先做准备阶段，以及准备阶段的目标、边界、产物和验收标准。读完后应能判断：当前仓库还没有进入算法开发，而是在为后续 A/B/C 三条主线建立清晰的项目管理基础。

## 核心结论

| 项目 | 结论 |
| --- | --- |
| 当前阶段 | PREP 准备阶段 |
| 当前重点 | 目标、需求、任务、目录、模板、验收规则 |
| 当前不做 | 机器人控制算法实现、大型第三方仓库下载、大文件提交 |
| 后续方向 | A 自研基础系统、B `legged_control`、C `unitree_rl_mjlab` |

## 三条主线

准备阶段完成后，后续 A/B/C 三条主线按统一结构推进。

| 主线 | 名称 | 准备阶段作用 |
| --- | --- | --- |
| A | 自研机器人运动控制基础系统 | 明确 Pinocchio、MuJoCo、OSQP、脚本、图表和验收标准 |
| B | `legged_control` 复现与拆解 | 明确 NMPC、WBC、状态估计、`ros-control` 的阅读和复现目标 |
| C | `unitree_rl_mjlab` 复现与拆解 | 明确 MuJoCo RL、Train、Play、Sim2Real、obs/action/reward 的拆解目标 |

## 阶段边界

| 类型 | 本阶段做什么 | 本阶段不做什么 |
| --- | --- | --- |
| 文档 | 生成准备阶段文档、任务表、风险表、验收清单 | 不写完整技术报告 |
| 代码 | 只创建目录和占位 README | 不实现机器人算法 |
| 开源项目 | 只记录用途、地址、阅读目标和复现策略 | 不下载大型第三方仓库 |
| 资源 | 规划 URDF、MJCF、mesh、视频、日志和权重管理 | 不提交大文件 |
| 环境 | 写清检查命令和推荐版本 | 不强制完成安装 |

## 本文用途

本文件提前记录环境、编译、训练、模型资源和项目执行风险，保证单点失败不会阻塞整个求职 baseline。

## 核心结论

| 风险类型 | 处理原则 |
| --- | --- |
| 环境风险 | 记录检查结果，必要时使用 Docker 或降级目标 |
| 编译风险 | 不隐瞒失败，保留日志和问题复盘 |
| 训练风险 | 优先 Play 和短训练，不追求大规模收敛 |
| 模型资源风险 | 先用小模型验证链路，再替换真实模型 |
| 仓库管理风险 | 大文件默认忽略，第三方源码不复制进仓库 |

## 风险与备选方案表

| 风险 | 可能原因 | 影响 | 备选方案 |
| --- | --- | --- | --- |
| `legged_control` 编译失败 | ROS、OCS2、依赖版本复杂 | B 项目无法跑 demo | 先完成文档拆解和源码阅读，保留编译日志作为复现记录 |
| `unitree_rl_mjlab` 训练慢 | GPU 不足或环境问题 | C 项目无法完整训练 | 优先跑 Play 或短训练，重点拆 obs/action/reward |
| MuJoCo 模型缺失 | MJCF 或 mesh 路径不一致 | A/C 仿真受阻 | 先用简单单关节或机械臂模型做 PD baseline |
| Pinocchio URDF mesh 报错 | mesh 路径或格式问题 | 模型加载不完整 | 先只加载 kinematic tree，不要求显示 mesh |
| ROS2 版本冲突 | Ubuntu 版本不同 | ROS 相关任务受阻 | 第一阶段不依赖 ROS2，把 ROS2 放到扩展 |
| Codex 一次写太多完整代码 | 提示词约束不够 | 学习失控、代码不可解释 | 所有提示词明确只生成 TODO 教学骨架 |
| 大文件污染 Git | 视频、mesh、日志、权重过大 | 仓库臃肿 | 准备阶段先写 `.gitignore` 和资源管理规则 |

## 风险分级

| 等级 | 定义 | 处理方式 |
| --- | --- | --- |
| 高 | 会阻塞某条主线运行 | 立即启用 fallback，保留日志 |
| 中 | 会影响结果质量但不阻塞学习 | 降低目标，先完成文档和小规模验证 |
| 低 | 只影响展示完整度 | 放入后续扩展 |

## 执行原则

| 场景 | 原则 |
| --- | --- |
| 编译失败 | 不隐瞒失败，记录系统、命令、报错、已尝试方案 |
| 训练不收敛 | 不强行调参到高性能，优先讲清 reward、obs、action 和 termination |
| 模型加载失败 | 降级到小模型，先验证数学链路 |
| 依赖冲突 | 优先隔离环境，必要时使用 Docker |

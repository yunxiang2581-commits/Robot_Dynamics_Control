# Documentation Placement Rules

## Stable Project Documents

Use `docs/00_project_management/` for repository-level status:

- `PROJECT_STATUS.md`
- `PROJECT_STRUCTURE.md`
- `PROJECT_ROADMAP.md`
- `DOC_PLACEMENT_RULES.md`
- `DOC_MIGRATION_CANDIDATES.md`

## Project A Documents

Use `projects/A_self_baseline/docs/` for A-specific technical docs:

- interface docs.
- pipeline contract.
- mink alignment notes.
- foundation validation explanations.

## Temporary Step Reports

Do not keep accumulating old step reports. After Step R-C, only keep current refactor reports that explain active state:

- `stepR_C_deletion_inventory_before_refactor.md`
- `stepR_C_complete_refactor_report.md`

Older step reports can be deleted once their useful state is migrated into stable docs.

## Output Files

Project outputs belong under `projects/A_self_baseline/outputs/` and should be regenerated by runnable steps. Old A04/A05 outputs were removed because A04/A05 are now interface TODO wrappers.
